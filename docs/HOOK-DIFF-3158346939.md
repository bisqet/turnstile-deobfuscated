# Hook vs no-hook branch diff, build 3158346939 (H140)

Research only. Every run here is the offline deterministic replay (`tools/chrome-run/run-plain.mjs` serving the captured bytes, `LIFT_SUBST` lift). Nothing is sent to CF and no token is produced. This document has counts, positions, paths and API names only. It has no field values. Value comparisons use a 32-bit FNV fingerprint per primitive field. The fingerprint exists only in scratch dumps.

## What "hook" means in this project

`RUN_HOOK` (header of `tools/chrome-run/run-plain.mjs`) installs what a stealth or instrumentation framework would add to a clean browser:

| variant | what changes |
|---|---|
| `webdriver` | Chrome `--enable-automation`, so `navigator.webdriver === true` |
| `native` | loud `Function.prototype.toString` override (sloppy `function toString(){...}`). It returns `"function () { [hooked] }"`, counts calls, sets `data-hook` / `data-ts` on `<html>` and defines `__tsCalls` / `__tsWd` globals |
| `native_stealth` (new, H140) | stealth-framework pattern: the wrapper returns the real native text for every function, including itself (WeakMap). It adds no globals and no DOM marks |
| `inert` (new, H140) | control: the same injection path (inline `<script>` spliced into the page plus CDP evaluate) running an empty IIFE |
| `runtime` | CDP `Runtime.enable` on every target |
| `RUN_HOOK_IN_WORKER=1` | the hook goes only into worker realms (`wnative`, `wstealth`, `wruntime`) |
| `headless`, `ua_headless` | environment, not a hook (`--headless=new`; HeadlessChrome UA) |

How the runs were traced: `RUN_LIFT_FT` (lift fieldTrace, default off, commit d97bda7). It dumps, per payload path, the type, the value fingerprint and the executed writer site. It also dumps per-site branch outcome counts (`br`) and labelled browser-API reads (`api`).

## Finding 2: the hook's side effects that other probes read

- **`<html>` attributes, payload `9.vWNIm6`.** [F/stage2/277_fn_navigator_227518.js:83-113](../vm/stage2/277_fn_navigator_227518.js#L83) reads the orchestrator's `PUUDF8["ht.atrs"]`. If that is missing, it reads `MC(..., document.body.parentNode)`. The result goes to `v67.vWNIm6 = arr_v40` (#228165). Under `native` the list gains 2 entries, which fits the hook's `data-hook` and `data-ts` marks. Under stealth it is unchanged.
- **`kNTL3`.** [F/stage2/324_bag_init_48fields.js:313-319](../vm/stage2/324_bag_init_48fields.js#L313) puts `document.body.attachShadow.toString().toLocaleString().toString()` (#478854-478900) into slot 7 of a list together with `compareDocumentPosition` / `Node` constant results. It combines the list and stores it as `kNTL3` (#478948). The fingerprint changes only under the loud hook.
- **Window property index, `1.QVHD7`.** The orchestrator helper `JwCUQ7` ([F/orchestrator.readable.js:1993](../orchestrator/orchestrator.readable.js#L1993)) inverts `getOwnPropertyNames(window ...)` into `{value-or-type-tag: [names]}`. The new `__tsCalls` / `__tsWd` globals and the changed values add 68 entries. For `webdriver`, the same index is the only thing that moves: `navigator.webdriver` changes bucket (+1 / -1).
- **Automation-global scan.** [F/stage2/095_fn_then_71987.js:261-268](../vm/stage2/095_fn_then_71987.js#L261) loops over the global key list (`Reflect.apply(...).length`: 1260, or 1262 with the hook) and returns `"wdhwX8"` when `v176[key] === 1`, otherwise `"MntR6"`. It read the two hook globals (`window.Object.create.__tsCalls` / `.__tsWd @ #73476`), but they are not on its list. No payload field changed because of this scan.

## Finding 3: the injection itself is visible (inert control)

The empty inline `<script>` that the harness splices into the page changes these, with no hook behaviour at all:
- [F/stage2/276_fn_document_227253.js:26-35](../vm/stage2/276_fn_document_227253.js#L26) loops over `document.head.childNodes` (8 to 9 nodes) and checks `nodeType === Node.COMMENT_NODE` with `nodeValue.includes(...)`.
- [F/stage2/174_fn_document_cb_166102.js:5-41](../vm/stage2/174_fn_document_cb_166102.js#L5) is a TreeWalker filter (`instanceof HTMLIFrameElement / HTMLFrameElement / HTMLObjectElement / HTMLEmbedElement`, giving `FILTER_ACCEPT` or `FILTER_SKIP`). It ran 96 to 97 times.
- Payload `14.CJkad9` (the documentElement/CSSOM-derived string, written at `op|198239`) changes with the injected text. It differs for inert, stealth and native.
- Payload `24.cDAn9` / `24.QsDgu4` / `24.rxAT4` come from the orchestrator-supplied `PUUDF8.pi.{pfp,sL,tL}` ([F/stage2/261_probe_24_helper_220653.js:23](../vm/stage2/261_probe_24_helper_220653.js#L23); `PUUDF8 = rp["wPr"]` at orchestrator.readable.js:10119). The two numbers change with any injected script. `pfp` also changes under the loud hook. These values are computed outside stage2, and H140 did not trace their origin.

A framework that patches through CDP `addScriptToEvaluateOnNewDocument`, with no page-HTML splice, would avoid Finding 3. Finding 1's shape checks would still catch it.
