## Verification classes

- **SHA-gated, executed from this text (`readExec`)**: all stage2 table fns since H133 (314) and, since H135, the gated stage1 fns (10). The file is byte-equal to `execSrc` in `subst-tab-h139.json` (sha256 = `execHash` = `readableHash`) and the runtime executes the statements of this text: `lift-subst-runtime.js` (`/*ERF-BEGIN*/` block) parses the file once per fn, requires every table step key exactly once, and runs each body step from the line that names it; jumps, branches, CALL, CLOS, RET and THROW keep their table successors. A changed statement changes the run (negative control in `evidence-h134.json`).
- **SHA-gated (compiled from this text)**: the other table fns. The table entries the runtime executes were compiled from the H122 text (sha256 = `compileSrcSha256` = `execHash` in the table); the runtime executes those entries, not the text. The file is that compile source with H132 display edits only: marks recounted from the H131 default, headless and canvas_noread traces (`[L dN hN cN]` = hit counts per run; `[L rN]` = no hit in those three runs but executed N times in the H122 reference-capture evidence), the 45 op138 operand reads shown as the derived register the table executes (`r204 /* derived; capture read t205_… */`), the stale `/* native */` tag dropped (`/* s2x */` where the step is an s2x entry), and try-handler regions appended as display-only catch blocks. The builder checks that the file minus those edits equals the compile source. Both SHA-gated kinds ran under the gate (entry-only XOR: compiled body or interpreter, never both) with the golden sha. Stage1 fns are compiled the same way (`s1|` bodies). Earlier READMEs said these fns "run from this text"; that was wrong for every fn before H132 and stays wrong for the compiled kind.
- **gated, not executed**: compiled and gated exactly like SHA-gated (the runtime would run the readable text if the entry were reached), but the reference flow never invokes the fn, so there is no execution evidence. The reason is recorded per fn in `index.json` (`notExecutedBecause`).
- **SC-verified, not SHA-gated (CF stack fingerprint)**: the fn stays on the interpreter under the default gate because CF hashes its own `Error.prepareStackTrace` capture, so a readable frame would change the fingerprint. Every executed lifted statement was compared per step by shadowcmp against the native handler, with 0 diffs and 0 errors. This is not SHA-verified.
- **translated-unverified**: readable translation with no fn-level execution proof.

H142 CALL binds and write set: a CALL whose return value is read as a local binds it on the call line (`NAME = cell[N](args);`); the runtime checks the bind after every normal return. On a normal return a stage-2 CALL changes only its return register and 12 table registers (`CALLCLOB` in `lib/erf-h142.mjs`, from execution); every other local keeps its value across the call, checked by chk-sound-h142 and by the runtime freshness check (erfStale). The exception edge keeps the full kill.

Statement marks (H132): `[L dN hN cN]` = the step ran N times in the default (d), headless (h) and canvas_noread (c) traces; `[-]` = in none of them. Stage1 readExec files carry the same ERF marks; the other stage1 files keep the H122 marks (`[L n]` lifted and executed n times, `[N n]` native, `[-]` not executed in the reference capture).

H143 multi-key while lines: `while ((P1, ..., [S, ]C)) {  // #a | #b #c | #d [marks]` - groups split by `|` map in order to the comma parts of the header; the last key of each group carries its part, the last group is the loop-exit branch (its statement is S when present, its condition C). Only `while` lines carry groups.
ERF lines (readExec fns) read `<statements>;  // #hpc:hkey:op ... [marks] +#hpc:hkey:op ...`. H134 renders the fn body as structured JavaScript: `if (C) { } else { }`, labelled blocks, loops, `try { } catch (caught) { }` (H139 name of r147), and `return E;` for the RET step. Loops have three forms: `for (;;) { }` left by `break` / `continue` (89 loops), `while (C) { }` (1, H135), and since H136 a `for (;;)` body whose last statement was `[S; ]if (C) { A } else { X }` with X ending in `return` / `break` / `continue` / `outside()` is written as the guard clause `[S; ]if (!(C)) { X } A` (43 rewrites in 34 fns; A runs when X is skipped, in both forms). A loop rewrite is kept only when the runtime parser derives the same steps, successors and BR arms from the new text (a negated condition with swapped arms is the same BR). There is no `for (init; cond; update)` and no `for-of`: the parser has neither form, and `for-of` reads `[Symbol.iterator]` and `next` once and calls `return()` on an early exit, which the manual `next()` / `done` loop does not do. The runtime derives every J / BR successor and BR condition from this text and checks CALL / CLOS / OP52 fallthroughs and try handlers against the table, so the structure is executed, not displayed. Non-readExec files keep the H132 form (`Lpc_key:` labels and gotos; display-only catch blocks). Notation, verbatim from the top of `readable-h143/stage2.verified-flow.js`:

the try-handler stack; callDepths = r194, the tryStack length saved per closure call; caught = r147, the caught
exception ("} catch (caught) {" is the catch arm the VM catch rule resumes at, with caught = the exception).

H137: the lets under "H137 proven reads" are reads of a register that stays rN elsewhere in the fn; each such read

Readability rewrites in readExec fns are proved by static dataflow over the whole fn CFG, never-run arms and try-handler edges included (H136; no trace facts): a register write is dropped only when it is overwritten on every path before the fn ends or throws; a temp is folded only when it has one use and is dead afterwards on every path. `chk-sound-h138.mjs` (which includes the `chk-sound-h136.mjs` and `chk-sound-h137.mjs` checks) re-derives this from the final table alone (1420 drops, 536 folds, 1839 constant uses, 0 unsound). Registers are shared VM state (one XOR mask per VM instance, `regX`), so a write that is only overwritten after the fn returns is still observable and is kept. Aliases name a cell only from executed member uses (evidence in the header comment); registers are not named because they are reused for unrelated values.

H133 fn locals: a register web (one live range of a register: its defs and the uses they reach, through branches, try-handler edges and calls) becomes a `let` local when it is live-in at no entry, crosses no CALL, is not written by a table-made def and is not the value a RET step returns. H134: a web whose only blocker was reaching RET is a local too (write-through keeps the register file the caller sees unchanged); `retLocals` counts them per fn. Each `let NAME /* rN */` is bound to its home register; `NAME = E` writes the local and the home register (write-through), and a read of NAME checks that the home register still holds the same value (`Object.is`), else the invocation aborts as a self-error (`erfStale`, 0 in every gate run). The VM register file is therefore the table program's at every step. Webs kept as `rN` are counted per fn in `index.json` (`erf.kept`). A local is named `<class>_vN` only when every value written to it in the three erfTypes diagnostic runs (default, headless, canvas_noread; box-local only) had one native class (for example `OffscreenCanvasRenderingContext2D` gives `ctx2d_vN`); the header carries one evidence line per name. Primitives, plain objects and mixed classes keep `vN`.

H137 proven reads: in a web kept as `rN`, a use whose reaching definitions (every CFG path, try-handler edges included) are only statement writes of the text, with no fn-entry value, no CALL / CLOS / OP52 value, no handler value and no table-made value, reads a local: the writes become `NAME = E` (write-through) and the use reads NAME (295 statement reads and 20 BR conditions in 17 webs; 475 uses in 26 webs stay `rN` because some other value reaches them). CALL and OP52 kill every register; a CLOS kills only the one register it writes (`clos-writes-h137.json`, derived for every CLOS site), so locals now live across closures that write other registers. OP52 steps have both successors in the CFG (hash hit: then arm; miss: fallthrough; the runtime asserts this). This is the strict-pipeline form of the tool-export pilot pass L1b (`$v(...)` wrappers and `guard(N)` calls): in this text the analogous noise is the raw register read. `chk-sound-h137.mjs` proves on every path that each `V(K)` read sees its home register still holding local K (22297/22297 reads fresh, 0 stale), and rejects mutated tables (write-through removed, locals swapped, register read turned into a local, read after a CLOS that writes the home; see `evidence-h137.json` `mutation`). The runtime check (`erfStale`) stays on.

H138 explicit sources: a register read kept as `rN` in H137 because the fn-entry value, a CALL result or a CALL / CLOS value reaches it now reads a local when that value is bound right after its source: `NAME = rN;` (a bind, written `LW(K, R(h))` in the table; `R(h)` is the home register, so the register file is unchanged) at the first J / BR body step after the fn entry or the CALL / CLOS step. Every definition reaching the later reads is then a statement write, so the H133 / H137 rules make them `NAME` (510 binds kept of 1483 candidates; a bind is dropped when its local would have fewer than 2 reads or its def stays in an `rN` web). OP52 now kills only the pc and key registers (text r169 / r141): the real op52 handler, run at every listing site on the miss and the hash-hit path, writes no other register, and runOp52 touches only machine fields (evidence in `evidence-h139.json` `op52`). `chk-sound-h138.mjs` strips the identity binds from both texts before the H136 diff, checks every `V(K)` read fresh on every path with OP52 killing pc / key only (22297/22297), and rejects bind mutants (bind reads another register, bind dropped, bind moved before its CALL / CLOS source, OP52 writing every home). Left as `rN`: VM registers 48 / 147 / 194, table operands, and reads whose bind would not pay off (`evidence-h139.json` `sources.leftReasons`).

H139 machine names: three VM registers are never fn locals and stay registers in every fn; H139 executed the real VM handlers on the captured bytecode to find what each is (none is this / scope / arguments / an accumulator). `tryStack` (r48) is the try-handler stack: TP pushes an entry, the end of a try body pops it, a closure call pushes a sentinel the catch rule pops, RET truncates it. `callDepths` (r194) holds the tryStack length saved per closure call (RET: `tryStack.length = callDepths.pop()`). `caught` (r147) is the exception the VM catch rule writes before it resumes at a catch arm. A fn that uses them carries `// machine NAME = rN, ...`; the runtime parser reads NAME as rN, and erf-machine-h139 keeps a rename only when the parsed statements of every step and the parsed control are identical to the unrenamed text (106 fns). chk-sound-h139 rejects any other name-to-register mapping.
