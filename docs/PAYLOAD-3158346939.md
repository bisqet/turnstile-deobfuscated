## 1. Structure

- One flat object (the bag, VM register r210) with **101 top-level keys**: **38 probe slots** `1`…`38` and **63 bag fields** (challenge context, timing, serialized state). There are 645 nested fields, 746 in total.
- Each probe slot is an object with a shared envelope (tag, config blob, status, start/end/duration, executor) plus the probe's own result keys. Probes 6, 11 and 25 carry the envelope only; their executors only run `win.eval`.
- Serializer `zT` writes JSON-like text and skips functions and `undefined`: 658 of 746 fields have a plaintext position; the rest are skipped slots.
- Plaintext length: 64600 bytes in the default gated run (sha `7ca3e0532109`), 65265 in the reference capture. Hooks change the length (for example 74048 under `native`).
- Client-side path: `zL` ([orchestrator.readable.js:10622](../orchestrator/orchestrator.readable.js#L10622), display [L14907](../orchestrator/orchestrator.display.js#L14907)) builds the last bag fields (`KHnWz9`, `GesyF4`, `oYcq1`; `bag_init_3fields` at pc 124041, [stage2/109_bag_init_3fields.js:64](../vm/stage2/109_bag_init_3fields.js#L64)), then `xo` → `zT` serializer → pad → `ukb`/`Tlvt6` TEA encryption → custom base64 with alphabet `zX[40]`. The result goes in the body of the challenge XHR POST ([ORCHESTRATOR §XHR flow](ORCHESTRATOR-3158346939.md#xhr-flow)), with the `cf-chl` and `cf-chl-ra` headers. Nothing was sent during this work; all runs were offline.

## 4. Notable fields

- `27.rLrku6` / `27.XEUHT5`: integrity checks over 184 native functions. One set looks at shape (`.arguments` access, `prototype`, own property names); the other matches `toString()` against `function name() { [native code] }`. `rLrku6` changes under `native_stealth`, so it catches even the "stealth" patching style. `XEUHT5` grows by about 9.4 kB under the loud `native` hook.
- `14.CJkad9`: a 7-frame `Error().stack` with line:column. Anything that adds or shifts script text moves the columns, so it differs under `inert`, `native_stealth` and `native`. The old HOOK-DIFF wording "documentElement/CSSOM-derived string" comes from the map label; H144 parses this field as stack frames.
- `1.QVHD7`: an index of every own property name on `window`, grouped by value or type tag (orchestrator `JwCUQ7`). New, missing or retyped globals show up here under `webdriver`, `native`, `headless` and `ua_headless`.
- `24.cDAn9` / `24.QsDgu4` / `24.rxAT4`: page-level fingerprint and script-length counters supplied by the challenge page (`PUUDF8.pi.pfp/sL/tL`), not computed in the VM. Any injected script changes them.
- `9.vWNIm6`: the attribute list of `<html>`. Extensions and hooks that tag the root element show up here (it differs under `native`).
- `kNTL3`: a top-level check that `attachShadow` still stringifies as native, combined with Node constants. It differs under `native`.
- `16.*`: WebGL vendor/renderer, parameter and extension blocks. Under `headless` seven of these status strings turn into fallback arrays (a type change), which makes software/headless GL easy to spot.
- `7.akeLU4`: the physical keyboard layout map (48 key codes → characters), from `navigator.keyboard.getLayoutMap()`. Entries go missing under `headless`.
- `30.StrX9`: the full `getHighEntropyValues()` client-hint dictionary (architecture, bitness, brands, fullVersionList, mobile, model, platform, platformVersion). Under `ua_headless`, `brands` and `fullVersionList` are added and `architecture`, `bitness` and `platform` change.
- `17.*`, `22.QsQH7` and `21.DFHHz4`: timezone results for four fixed historical years (likely exposing the tz database and the real zone; inferred), 184 Math precision results (engine/CPU) and a full WebRTC offer SDP (about 6.4 kB, the largest single string; inferred).
- Probe 26 reads battery state (`charging`, `chargingTime`, `dischargingTime`, `level`), six `matchMedia` queries, the navigation type and `document.referrer`. Probe 33 sends the whole Network Information record.

### Why CF collects this, by category

**Window / global-object inventory** (66 fields; main purposes: device fingerprint entropy (stable per machine) 51; automation/webdriver detection 4; hook/patch detection on native functions 4). Probe 1 inverts Object.getOwnPropertyNames(window) into buckets. The set of globals is a build/version fingerprint, and automation frameworks, injected scripts and hooks add or remove globals; in our runs individual buckets moved with the webdriver flag, hook injection, headless mode and UA preset. The iframe-realm checks compare a fresh realm with the main one.

**Workers & secondary realms** (23 fields; main purposes: cross-realm consistency (worker vs main) 19; device fingerprint entropy (stable per machine) 2; probe envelope bookkeeping 1). Probes 2, 4, 5, 34 and 36 run code in a Worker and send its navigator/hardware view next to the main-thread one. Spoofing usually patches only the main realm, so a worker reply that disagrees (UA, cores, memory) exposes it; the worker reply moved with UA and hardware changes in our diffs.

**JS engine & Math precision** (5 fields; main purposes: timing/human-ness / VM anti-tamper 3; device fingerprint entropy (stable per machine) 2). Math precision on fixed inputs is constant per engine/CPU and acts as an engine check that should match the claimed UA. bmma1 is an eval/global-this consistency number that probe 27 compares with slot 21 (VM anti-tamper).

**Probe envelope & bookkeeping** (358 fields; main purposes: probe envelope bookkeeping 356; hook/patch detection on native functions 2). The envelope (tag, config blob, status, start/end/duration, executor) is bookkeeping: it tells the server which probes ran, whether they failed and how long they took. Durations double as a weak timing signal; status codes change when a probe throws (e.g. under hooks).

**Navigator, UA & client hints** (63 fields; main purposes: device fingerprint entropy (stable per machine) 50; consistency check vs UA/client hints 11; headless detection 2). The UA string and high-entropy client hints are reported side by side so they can be checked against each other and against engine behaviour; client hints moved with the UA preset in our diffs. The keyboard layout map adds per-machine entropy and differed in headless mode.

**DOM, document & CSS** (27 fields; main purposes: integrity of the challenge script itself (stack/injection) 12; headless detection 7; device fingerprint entropy (stable per machine) 5). The DOM behaviour battery, image-load checks and <html> attribute list distinguish real rendering engines from emulated/headless ones and detect attributes injected by extensions or hooks (observed under hook injection).

**Fonts & text metrics** (14 fields; main purposes: device fingerprint entropy (stable per machine) 10; timing/human-ness / VM anti-tamper 3; probe envelope bookkeeping 1). Installed fonts and text metrics are classic per-machine entropy; the font-probe timing lists are run-to-run timing data.

**Network information** (10 fields; main purposes: device fingerprint entropy (stable per machine) 9; headless detection 1). Connection type and online state describe the network profile; plausibly compared with the IP's network type server-side (not knowable).

**Stack / error / devtools fingerprints** (13 fields; main purposes: automation/webdriver detection 8; integrity of the challenge script itself (stack/injection) 2; headless detection 2). Error().stack line:column positions move when the challenge script is wrapped or code is injected (observed under hook injection and stack-limit changes). Probe 37 traps console/devtools, Proxy and toString, which change when harness wrappers are visible.

**Canvas & WebGL** (16 fields; main purposes: headless detection 9; device fingerprint entropy (stable per machine) 7). WebGL vendor/renderer, parameters and canvas pixels identify the GPU stack; they moved with GPU readback changes, and headless/software-GL modes produce distinctive values.

**Locale, Intl & timezone** (20 fields; main purposes: device fingerprint entropy (stable per machine) 19; probe envelope bookkeeping 1). Timezone, Intl formatting and historical Date offsets give locale entropy and can be checked against the IP's geography server-side; they moved with timezone and locale changes in our diffs.

**Crypto & audio hashes** (10 fields; main purposes: timing/human-ness / VM anti-tamper 5; device fingerprint entropy (stable per machine) 5). Audio-render digests are device entropy. The four SHA-256 digests of fixed inputs are constants: they only confirm that crypto.subtle behaves like a real browser.

**Performance & memory** (10 fields; main purposes: integrity of the challenge script itself (stack/injection) 6; timing/human-ness / VM anti-tamper 2; device fingerprint entropy (stable per machine) 1). Navigation timing, body sizes, Trusted Types/nonce checks and navigation type describe how the page was loaded, whether it was rewritten, and whether it is a reload/replay.

**WebRTC & media** (11 fields; main purposes: device fingerprint entropy (stable per machine) 10; probe envelope bookkeeping 1). WebRTC offer/ICE and codec lists expose network interfaces and the media stack; they help detect proxies/VMs and add entropy.

**Page-supplied info (PUUDF8)** (24 fields; main purposes: challenge binding (server data echoed back) 21; integrity of the challenge script itself (stack/injection) 3). PUUDF8 page info is supplied by the challenge page and echoed back to bind the payload to it; its page-fingerprint and script-length counters changed when scripts were injected.

**Device, display & sensors** (15 fields; main purposes: device fingerprint entropy (stable per machine) 13; headless detection 1; probe envelope bookkeeping 1). Media queries, battery and permission states are device/display entropy; permission and battery states are commonly abnormal in headless/VM setups (hypothesis).

**Native-function integrity checks** (7 fields; main purposes: hook/patch detection on native functions 7). Probe 27 tests a long list of native functions for patches: .arguments access, prototype===undefined, own property names and toString containing "[native code]". These lists changed under the hook modes in our diff runs.

**Challenge context & session state** (46 fields; main purposes: challenge binding (server data echoed back) 41; probe envelope bookkeeping 4; timing/human-ness / VM anti-tamper 1). Members of the server's challenge object are echoed back so the payload is bound to this challenge instance; serialized state strings carry the same binding.

**Timing & performance clocks** (8 fields; main purposes: replay protection / freshness (timestamps) 5; timing/human-ness / VM anti-tamper 3). Differences between challenge timestamps and Date.now() at send show how old the challenge is (freshness/replay); performance.now() deltas add execution-timing data.
