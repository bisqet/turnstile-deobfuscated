# As-built pipeline: how `final/` was produced for build 3158346939

This document describes what the repo actually ran to get from the captured Cloudflare Turnstile page and its
encrypted VM bytecode to `tools/deob-auto/out/3158346939/final/`. Steps are in execution order. Every script, file
and number comes from the repo: the scripts' usage lines and headers, `final/README.md`, `final/evidence-h*.json`,
`docs/build-3158346939.md`, `docs/ORCHESTRATOR-3158346939.md` and `git log`.

Each step lists what it does, input → output, the tools/APIs used, condensed pseudocode (not verbatim), a
before/after snippet, how it was verified, and its metrics.

**Local-only inputs.** Some inputs never enter git:
- the captures;
- the pin tables;
- run traces;
- the per-op table before H105;
- the erfTypes record.

They are marked **[local]**. Everything after `subst-tab-h131.json` is committed except those traces and pins.

**Redaction.** No payload values, captured strings, pins, ray ids, fo URL paths or challenge-options global
contents appear here. `1.QVHD7` bucket keys are written as `<vNN>`. Short hashes such as `7ca3e0532109` are sha256
prefixes of our own outputs: the golden pre-encryption payload of the gate.

## 1. Orchestrator normalize (read-only view)

**What.** Execute the orchestrator's own string decoder, fold its opaque seed and pretty-print the ~590 KB one-line
script. This text is the base for every later orchestrator file (step 13).

**Input → output.** **[local]** captured orchestrator `.dat` + `api.js` + fo dir →
`out/3158346939/int-plain-1.orchestrator.readable.js` (redacted, read-only) and `api.readable.js`.
Command: `node readable-run.mjs <orch.dat> <api.js> <foDir> <outPrefix>`.

**Tools.** `@babel/parser`, `@babel/traverse`, `@babel/generator`; Node `vm.runInContext` in an isolated context
(`lib/sandbox.mjs`: stubbed browser globals, network APIs throw).

```text
ast = babel.parse(js)
for decl  K = (a=>a).length + N           : env[K] = N + 1            // opaque seed
for const binding with constant init      : env[id] = evalConst(init) // B = M ^ K, C = ~B
dec = findStringDecoder(ast)              // data flow: outputs feed property access
f   = vm.runInContext(dec.source, isolatedContext)     // the real decoder
for call a0(`lit`)                        : replace with StringLiteral(f(lit))
for lazy cache X || (X = a0(`lit`))       : inline the literal
fold expressions built only from numbers and env constants; generate(ast)
```

Before/after (shape only):

```js
// before
q[a0(`<enc>`)](r, B ^ 6)        // B = M ^ K, K = (a => a).length + N
// after
q["<decoded name>"](r, <folded number>)
```

**Verified by.** `readable-run.mjs` E1 (raw vs readable in a fresh sandbox, same stop) and E2 (stage-1/stage-2
natural traces hashed equal: 149 = 149, 197 = 197 steps).

**Metrics.** 4486 `a0(...)` calls replaced (0 undecodable), 1420 lazy caches inlined, 21413 constant expressions
folded; `api.js` 381 folds.

## 2. fo decrypt and build constants by execution

**What.** Turn the fo response into VM bytecode and recover the per-build constants by running real orchestrator
fragments; check them against `known.json`.

**Input → output.** **[local]** fo ciphertext + its ray → stage 1 bytecode (5978 B) and stage 2 bytecode (483067 B),
in memory only; `validation-report.json` (constants, each with method `executed`).
Commands: `node index.mjs <orch.dat> --fo <file> --ray <ray> --out report.json`, `node run-all.mjs` (every captured
build vs `known.json`).

**Tools.** Node `Buffer` base64, Node `vm`; `tools/decrypt-fo.mjs` (also imported by `build-subst-table.mjs`).

```text
// tools/decrypt-fo.mjs
Hu = 32; for ch in (ray + "_0"): Hu ^= code(ch)
Hx = base64decode(cipher) as binary string
layer1[i] = chr( mod( (Hx[i] & 255) - Hu - i + 65535, 255 ) )
bytecode  = base64decode(layer1)
// constants (lib/*.mjs), each from executed code
emb/magic : run the pool byte-reader for emb in 0..255, read magic + TEA delta at executed compare sites
pool poly : execute the real key-update expression on many inputs, fit degree 1/2 by finite differences
wabXor    : run the real pool decode on the fo blob for each candidate, keep the one that scores as text
jumpXor   : boot orchestrator (seeded Math.random), clone VM, run all 256 opcodes with random operand bytes,
            keep handlers whose new pc is a 24-bit target; X = newKey ^ dec(next byte); all trials must agree
handlers  : count numeric case labels of the dispatcher switch
```

Before/after: ciphertext (base64 text) → bytecode bytes whose pool decodes to 255 strings with the derived
constants.

**Verified by.** `run-all.mjs` compares every constant with `known.json`: OK on `int-plain-1` and `int-headless-1`.

**Metrics.**
- emb 235, wab xor 119, pool poly A 28989 / B 49967 / offset 233, jumpXor 99;
- jump handlers 48, 53, 69, 180, 210;
- magic `[183,76,57,162]`, handlerCount 76, 255 pool strings.

Later steps do not decode operands with these constants: the disassembler executes the real handlers (step 5).

## 3. Run environment (used by every Chrome step)

**What.** Replay the captured page offline in stock Chrome, deterministically, and read the pre-encryption payload
(`Ojb`) at the second fo POST.

**Input → output.** **[local]** captures (`run2.sh` defaults `CAP`/`HOST` point at `signal-diff/re/...`) + env
options → one JSON result per run, kept in `/workspace/turnstile-scratch` (never committed). It holds the `Ojb`
sha256, `plainLen` and runtime counters, plus an optional trace (`RUN_TRACE_DUMP=1`).

**How it is actually launched.**
- `OUTER=<s> RUN_TMO=<ms> sh tools/chrome-run/run2.sh <out.json> [ENV=VAL ...]`.
  - The script enters a fresh user+net namespace (`unshare`) where only loopback is up.
  - It starts `run-plain.mjs`, which launches **stock Chrome** (`chrome-launch.mjs`, apt `google-chrome`, fresh
    profile, `xvfb`, `--window-size=1280,900`).
  - `run-plain.mjs` drives Chrome over **raw CDP** through a vendored WebSocket shim. There is no stealth layer.
- Gates: `. gate-vclock.sh` exports the default gate environment: virtual scheduler, virtual clock, and
  invisible-pin replay from a **[local]** oracle (`RUN_INV_ORACLE`). Then `ojb-matrix.sh` runs the labels
  (`baseline`, `subst`, `tracebase`, `shadowcmp`; `LIFT_SUBST=<table>`; `OJB_VAR`) through `run2.sh`. All gate
  commands run under `env -i`.

**CDP methods used** (`run-plain.mjs`, `chrome-launch.mjs`).
- `Target.setAutoAttach`, `attachToTarget`, `createTarget`, `getTargets` (page, iframe, workers);
- `Fetch.enable`, `requestPaused`, `fulfillRequest`, `failRequest`;
- `Page.enable`, `navigate`, `addScriptToEvaluateOnNewDocument`;
- `Runtime.enable`, `evaluate`, `runIfWaitingForDebugger`;
- `Emulation.setVirtualTimePolicy`, `setCPUThrottlingRate`, `setTimezoneOverride`, `setLocaleOverride`,
  `setHardwareConcurrencyOverride`, `setUserAgentOverride`;
- `Network.enable`, `setUserAgentOverride`;
- `Debugger.enable`, `setBreakpointByUrl` (conditional), `resume`;
- `Log.enable`.

**Pins are CDP + JS shims.**
- CDP sets the time zone, locale, CPU throttle, UA preset and hardware concurrency.
- Realm scripts are injected before any document script:
  - `determinism-src.js`: Date, `performance.now`, `Math.random` and `getRandomValues` from seeded sequences;
  - `invisible-pins-src.js`: Date/perf record and replay, LoAF filter, `deviceMemory`;
  - `vsched-*-src.js`: virtual scheduler and clock;
  - `recorder-src.js`;
  - `lift-subst-runtime.js`.
- The shims keep native `Function#toString`, descriptors and names.
- Pin values are **[local]**.

**What is served.**
- **`RUN_RAW` labels (baselines):** the captured page and orchestrator, byte for byte.
- **subst / tracebase / shadowcmp labels:** the orchestrator is served as an **instrumented, column-fitted text**.
  `page.mjs buildInstrumentedHtml` runs `instrument(text, {map, colFit})`, then `injectEncryptHooks`, then
  `anchorColumns` (H117 colFit). colFit puts every token at its column in the original VM text, so CF's own stack
  capture (`14.CJkad9`) is computed rather than replayed.
- **With `RUN_OOL=1 RUN_ORCH_READABLE=<file>`:** that text is the executable readable from step 13. Its posmap
  re-points the instrumentation map to the original columns, and the pin table (`RUN_ORCH_PINS`, **[local]**) is
  installed by an out-of-line script.
- **The fo bytecode** is always served unchanged.

```text
// run-plain.mjs (condensed)
launch chrome in netns; Target.setAutoAttach(all, waitForDebugger)
per target: Fetch.enable ; Emulation pins ; addScriptToEvaluateOnNewDocument(shims, recorder, lift runtime)
            Runtime.runIfWaitingForDebugger
on Fetch.requestPaused(req):
    captured route      -> fulfillRequest(local body)        // orchestrator raw or instrumented (see above)
    1st fo POST         -> fulfillRequest(captured response)
    2nd fo POST         -> record length only, halt          // the payload never leaves the box
    anything else       -> failRequest(BlockedByClient)
Ojb = plaintext seen by the injectEncryptHooks wrappers (zT / xo / ukb) -> sha256, plainLen
```

Before/after (determinism): repeated runs used to differ by time, scheduling, hardware and stack columns. Since
H116/H117 they give 15/15 identical `7ca3e0532109` / plainLen 64600 at CPU throttle 1, 2 and 4.

**Verified by.** VERIFY 23/23 (`obs-test-vsched-chrome.mjs`: every wrapped API vs a clean realm), INVC 10/10
(`obs-test-invisible-pins-chrome.mjs`), INVN 13/13 (`obs-test-invisible-pins.mjs`, Node `vm`).

## 4. Opcode semantics by executing the real handlers

**What.** Decide what each opcode does by running its real handler, not by reading the obfuscated source.

**Input → output.** Orchestrator `.dat` → `out/3158346939/semantics.int-plain-1.json` (+ `opcode-table.json`).
Commands: `node handlers-run.mjs <orch.dat> <semantics.json>` then
`node frame-run.mjs <semantics.json> <stage1.json> <stage2.json>` (updates in place).

**Tools.** Node `vm` (`lib/vm-harness.mjs boot`), recording `Proxy` operands; `lib/handler-semantics.mjs`,
`handler-relations.mjs`, `handler-branch.mjs`, `handler-frame.mjs`, `handler-call.mjs`.

```text
operator : run the handler on random bytecodes with number/string/object vectors;
           accept iff exactly one library operator (operand order included) reproduces every write
relation : tagged inputs; accept iff one template (copy, imm, strlit, concat, prop chain, call/new,
           push/pop, throw) holds in every trial, repeated with other inputs
branch   : 12 bytecodes x 12 operand vectors: successor pc must depend on the predicate only
frame    : handlers touching cell table / try stack / depth stack: run twice per real site with
           real-shaped state; accept a template only if all effects match at every site
site-call: op138 proposes rD = rO.NAME(args) | rF.call(rT,args); two concrete runs must agree
```

Example: the frame verifier (14 sites) settled op245 as **return**: `r162 = rX; r48.length = r194.pop(); pc = NaN`.

**Metrics.** 76 opcodes (75 numeric case labels + op 1); 68/76 verified in the opcode table. Sites the compiler
could not translate later get per-site semantics derived by execution (step 7).

## 7. Whole-function bodies, derived sites, stage 1 → `subst-tab-h131.json`

**What.** Compile each VM function into one body the runtime runs from entry to RET/THROW instead of the
interpreter. The choice is made per invocation, at entry only: readable body or interpreter, never both. Sites the
compiler cannot translate get statements derived by running their real handlers offline.

**Input → output.**
- `compile-fn-bodies-h128.mjs <base-tab> <readable-h122/stage2.verified-flow.js> <out-tab> [report]` writes
  `fnBodies` keyed `entryHpc:entryHkey`, each `{readableSrc, readableHash, execSrc, execHash, stepKeys, byHk}`.
  Env: `H126_DER=<derived-sites.json>`, plus call modes and native sites.
- `derive-sites-h128.mjs <foDir> <listing.json> <out.json> [pinsIn pinsOut]` writes
  `out/3158346939/derived-sites-h1NN.json` (committed: `dec/o66/o69/o138/o249/u/x`) and a pins file **[local]**.
  Constant sites become `KP(m<pc>k<key>)`.
- Stage 1 (H130):
  - `H130_STAGE=1 derive-sites-h128.mjs ...`;
  - `call-mode-sites.mjs <foDir> <listing> <out>`;
  - `pin-redacted-sites.mjs <foDir> <listing> <pins>` **[local]**;
  - `compile-fn-bodies-h128.mjs` on the stage-1 view;
  - `merge-stage1-fnbodies-h130.mjs <gate-tab> <s1-compiled> <out>` → `subst-tab-h130.json` (keys `s1|hpc:hkey`).
- H131 adds derivation rules to `derive-sites-h128.mjs` (env `H131_138`, `H131_53`, `H131_XOPS`) →
  `derived-sites-h131.json`.
- Then `node merge-stage1-fnbodies-h130.mjs <stage2 table compiled over the H131 derivation> subst-tab-h130.json
  out/3158346939/subst-tab-h131.json` writes the **base table** of every later step.

**Tools.** Node `vm`; `lib/exec-lift-h128.mjs makeExecLift`. It runs the real handler at the site: 12 hashed numeric
runs plus 1 string run, and the result must fit one canonical form.

```text
repeat                                            // derive <-> compile until the target set stops growing
    targets = sites the compiler reported as missing (native stmt, unexecuted successor, call guard)
    for site in targets: stmt = execLift(realHandler, site)  // accept only if all runs fit one form
    fnBodies = compile(readable-h122, table + derived)
until targets unchanged                           // 1106 targets
runtime at fn entry: fnBodies[fn] && pins ok ? run body to RET/THROW : interpreter
                     fnBoth / fnPartial must stay 0
```

```text

after : fnBodies["<entryHpc>:<entryHkey>"] = { stepKeys:[...], execSrc:"...", execHash:"…" }   // whole fn
```

## 8. ERF: the readable text is what runs (`subst-tab-h142` → `subst-tab-h143`)

**What.** Rewrite each gated body as structured JavaScript (if/else, labelled blocks, loops, try/catch, locals,
